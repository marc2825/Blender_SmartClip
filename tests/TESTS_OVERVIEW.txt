Smart Clipping — Tests Overview
================================

Three test scripts are provided: automated headless (CI), automated UI (local, opens a
window), and a scene setup for manual interactive validation.


────────────────────────────────────────────────────────────────────────
1. headless_test_runner.py  (automated, no display required)
────────────────────────────────────────────────────────────────────────

Run all cases:
  blender --background --factory-startup --python tests/headless_test_runner.py

Run a single case:
  blender --background --factory-startup --python tests/headless_test_runner.py -- --case <name>

Test cases
----------
scene_props
  Verifies that all seven Scene properties are registered after addon load:
  smartclip_enabled, target_scope, target_collection, smartclip_runtime_info,
  smartclip_align_x, smartclip_align_y, smartclip_align_z.

scope_self
  Sets Target Scope = SELF and builds the KD-Tree.
  Object Mode: the moving object is never a target, so the tree is empty.
  Edit Mode (moving vertex indices given): all 8 verts are inserted and only the
  moving ones are excluded.

scope_selected
  Sets Target Scope = SELECTED with two selected objects and one unselected.
  Asserts only the non-active selected object's vertices appear in the tree;
  the unselected object is excluded.

scope_visible_sort
  Sets Target Scope = VISIBLE with three cubes at different distances.
  Asserts that the other objects are inserted nearest-first (distance sort
  order), the active object is skipped, and the point count equals 16.

budget_fallback
  Sets vertex budget to 8 (= one cube) with two target cubes visible.
  Asserts the nearest cube fills the budget and the other one appears in
  bounds_objects with only BOUNDS-type points.

scope_collection
  Creates two collections (SC_Test_A, SC_Test_B) and sets Target Scope = COLLECTION
  pointing to SC_Test_A.
  Asserts only the two objects in SC_Test_A appear as snap candidates (16 verts total).

stress_100k
  Creates a 320×320 grid mesh (~102 400 verts) exceeding the 50 000-vert budget.
  Asserts the heavy mesh is down-sampled into the budget (partial_objects) plus its
  9 bounds points. Build elapsed time is printed for performance reference.

budget_partial
  Budget 108 with a cube, a 400-vert grid and a far cube. The grid crossing the
  limit is sampled into the remaining 100 slots; the far cube gets bounds only.

scope_collection_recursive
  COLLECTION scope includes objects of nested child collections.

edit_mode_sync
  Adds a vertex in Edit Mode without leaving it; the tree must contain it
  (edit mesh flushed) and exclude it by its index.

parent_space_delta
  World-space deltas are converted into the parent space of `location` for a
  child whose parent was transformed after parenting.

constraint_helpers
  Axis / plane constraint masking helpers.

axis_align_gate
  Axis Align only suggests values within the pixel threshold, prefers the closest
  reference vertex, and skips the axis parallel to the view direction.

axis_align_dense
  The nearest alignment value is found even when thousands of values lie on one
  side of it.

find_hit_cap
  The per-query projection cap does not count excluded (moving) points.

Exit behaviour
--------------
  Exits with code 0 if all selected cases pass, code 1 if any fail.
  Individual PASS / FAIL lines are printed for each case.


────────────────────────────────────────────────────────────────────────
2. ui_operator_test.py  (automated, needs a display; opens a window briefly)
────────────────────────────────────────────────────────────────────────

Run:
  blender --factory-startup --enable-event-simulate --python tests/ui_operator_test.py

Drives the modal operator through simulated mouse / keyboard events and checks:
  - Shift+G starts the operator
  - a child whose parent was transformed follows the mouse exactly (no parent-space
    mix-up) and ESC restores it
  - orbiting the view mid-move does not make the object jump
  - an X constraint holds in world space; LMB confirms
  - holding RMB hard-snaps exactly onto a target vertex
  - Edit Mode moves the selected vertex and ESC restores it
  - no Python errors were printed (e.g. from draw handlers)

Set SMARTCLIP_UI_SCREENSHOT_DIR to save constraint.png / hard_snap.png overlays.
Exits with code 0 if all checks pass, 1 otherwise.


────────────────────────────────────────────────────────────────────────
3. manual_ui_setup.py  (interactive, opens Blender with a prepared scene)
────────────────────────────────────────────────────────────────────────

Run:
  blender --python tests/manual_ui_setup.py

What the script sets up
-----------------------
  SC_Active        — cube at origin; this is the object you move during tests
  SC_Near_X        — cube at (4, 0, 0); tests X-axis alignment
  SC_Near_Y        — cube at (0, 4, 0); tests Y-axis alignment
  SC_Near_Z        — cube at (0, 0, 4); tests Z-axis alignment
  SC_Diag          — cube at (4, 4, 0); tests free/diagonal snap
  SC_Heavy_100k    — 320×320 grid at (25, 0, 0); triggers BOUNDS fallback
  SC_COL_A/B       — cubes in collection "SC_Manual_Refs"; tests COLLECTION scope

  Preferences: max_vertex_budget=50000, snap_distance_px=30
  Scene: smartclip_enabled=True, target_scope=VISIBLE
  Active object: SC_Active (selected, others deselected)

Validation checklist
--------------------
  [ Soft/Hard Snap ]
    1. N-Panel > Tool > Smart Clipping: Enable Smart Clipping ON, Scope=VISIBLE.
    2. Press Smart Clipping Move (or Shift+G). Move toward SC_Near_X/Y/Z/Diag.
    3. Purple guide and soft pull toward the candidate should appear.
    4. Hold RMB near a candidate — guide turns cyan (hard snap).
    5. LMB or Enter to confirm; ESC to cancel and restore position.

  [ Axis Align Mode ]
    6. N-Panel: enable Axis Align Z only.
    7. Run Smart Clipping Move, move freely — z=4.0 (SC_Near_Z) should be suggested.
    8. A dashed line from the alignment point to the reference vertex should appear.
    9. Disable Z, enable X — x=4.0 suggested (SC_Near_X and SC_Diag).

  [ Axis / Plane Constraint ]
   10. Start a move, then press X — movement locks to X axis (red line appears).
   11. Press X again to release. Try Y and Z similarly.
   12. Press Shift+X — movement locks to the YZ plane.
   13. Combine constraint with Axis Align and Hard Snap.

  [ Budget ]
   14. N-Panel runtime info should show "Budget exceeded" — SC_Heavy_100k is sampled.

  [ Collection Scope ]
   15. Change Scope=COLLECTION, collection=SC_Manual_Refs.
   16. Only SC_COL_A and SC_COL_B should appear as snap candidates.

  [ Edit Mode ]
   17. Tab into Edit Mode on SC_Active, select some vertices.
   18. Run Smart Clipping Move — selected verts move; unselected verts snap as targets.
